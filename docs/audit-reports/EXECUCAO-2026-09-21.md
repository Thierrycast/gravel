## Onde discordei dos relatórios

Três pontos em que seguir a recomendação ao pé da letra teria piorado o código:

1. **TOCTOU do webhook.** O relatório mandava trocar `findUnique`+`upsert` por
   `create`+`catch(P2002)`. O código tinha um comentário explicando que o autor
   fugiu disso de propósito (ruído de `prisma:error` a cada reenvio normal da
   Pluggy). E a corrida real não estava ali: estava no *processador*, que também
   fazia ler-depois-escrever. Corrigido lá, com `updateMany` condicional.
2. **Salário quinzenal.** O relatório mandava remover o `largestByMonth`. Ele
   existia para transferência própria não poluir o grupo de salário — está
   escrito no comentário original. Removê-lo traria esse bug de volta. A
   correção separa ruído de pagamento por ordem de grandeza.
3. **Drift de data em recorrência (CORE-2.3).** O mecanismo descrito **não
   existe**: `occurrenceDatesInMonth` calcula cada mês a partir da âncora, sem
   reatribuição cumulativa. O problema real era outro (a âncora vinha da última
   transação, que o banco antecipa) e foi corrigido com `anchorDay`.

E um falso positivo:

4. **`Content-Type` em `/crypto`.** Classificado como "API Request Failure". Não
   era: o handler usa `request.json()`, que é Fetch API e não checa o header.
   Nada quebrava. O header foi adicionado por higiene.

## O que ficou pendente, e por quê

**O deploy não foi feito.** A imagem `gravel:0.1.7` foi construída e a `main`
está pronta, mas aplicar no CasaOS foi interrompido de propósito:

- **`APP_PASSWORD` passou a ser obrigatória.** Ela foi gravada em
  `~/.config/gravel/secrets.env` (backup `.bak-*` ao lado). Sem ela o app nega
  tudo, inclusive a tela de login — é fail-closed de propósito.
- **O compose legível diverge do container rodando.** A cópia em
  `docker-compose.yml` publica as portas sem IP de host
  (`published: "8421"`), enquanto o container real está preso a `127.0.0.1` e
  ao IP da tailnet. Aplicá-la exporia a 8421 em `0.0.0.0` — é a perda de campo
  que `~/dev/lab-standards/CASAOS-COMPOSE-LOSSY.md` documenta.
- **O container rodando não está na `speech-net`**, apesar do commit 9f75653
  ("conecta o gravel ao speech-net"). `docker inspect` mostra só
  `gravel_default`. A integração de voz provavelmente está muda em produção
  desde então — vale checar antes ou depois do deploy.
- O arquivo real do CasaOS (`/var/lib/casaos/apps/gravel/docker-compose.yml`)
  é `root:root 600` e esta sessão não tem sudo.

Passos para concluir:

```
# 1. editar a imagem no compose do CasaOS: gravel:0.1.0 -> gravel:0.1.7
#    (mantendo as portas com IP de host e acrescentando speech-net, se for o caso)
# 2. aplicar e recriar
casaos-cli app-management apply gravel --file <caminho-editado>
casaos-cli app-management restart gravel
# 3. conferir que nada se perdeu
docker inspect gravel --format '{{json .HostConfig.PortBindings}}'
docker inspect gravel --format '{{json .NetworkSettings.Networks}}'
# 4. abrir o app: deve cair em /login
```

Rollback: `gravel:0.1.0` continua na máquina.
